# V1 Spec: FMS Calibration (7 Actions Baseline)

## 1. Goal

构建一个可落地的 FMS 标定程序（Calibration），完成 7 个 FMS 动作视频的片段级自动分析与双人审核标注，形成可持续增长的高质量标定样本库，并让 AI 评分逐步逼近人工评分规则。

## 2. Product Scope (V1 In Scope)

- 支持 7 个 FMS 动作的统一标定闭环：
  - `deep_squat`
  - `hurdle_step`
  - `in_line_lunge`
  - `shoulder_mobility`
  - `active_straight_leg_raise`
  - `trunk_stability_push_up`
  - `rotary_stability`
- 支持上传单人、单动作视频（视频中允许出现多个重复片段）。
- 支持用户输入分析区间（开始秒、结束秒）。
- 系统自动完成片段切分、每片段机位识别（front/side）、每片段 AI 建议评分。
- 提供片段列表与播放器，支持逐片段循环播放与评分复核。
- 每个片段必须记录三份评分：AI、人工审核员 A、人工审核员 B。
- 完成全部片段复核后可入库，入库粒度为“动作片段”。
- 入库数据用于后续 AI 校准学习。

## 3. Out of Scope (V1)

- 直播实时评分系统（属于第二个程序，后续阶段）。
- 移动端原生 App 发布（V1 先做 Web Calibration 工具）。
- 自动仲裁工作流（V1 对三方全不一致样本直接标记无效，不自动仲裁）。

## 4. Users and Roles

- 标定员（认证 FMS 训练师）：执行视频复核与人工评分。
- 系统管理员（后续）：查看样本统计、模型版本、入库批次。

## 5. Workflow

1. 用户选择动作（7 动作可选）。
2. 用户上传视频并设置分析区间。
3. 系统在区间内执行：重复检测与切分、片段级机位识别、片段级 AI 初评。
4. 用户逐片段查看（循环播放）并输入/确认人工评分。
5. 人工 A 与人工 B 完成全部片段评分后提交入库。
6. 系统按裁决规则生成有效训练标签并写入样本库。
7. 无效样本保留原始记录，不进入训练标签集。

## 6. Functional Requirements

- `FR-001` 动作选择：提供 1-7 动作入口，均可进入分析流程。
- `FR-002` 视频上传：支持常见视频格式，完成基本可解码校验。
- `FR-003` 分析区间：开始/结束秒必填，系统仅处理该区间。
- `FR-004` 片段级处理：输出片段列表（序号、起止时间、机位）。
- `FR-005` 机位识别：同一视频内可正/侧面混合，必须按片段独立识别。
- `FR-006` 播放与导航：支持片段点击切换、循环播放。
- `FR-007` AI 评分：输出细分项评分与总分建议。
- `FR-008` 双人审核：人工 A/B 均需给出总分（1/2/3）与评论；细分项由系统保留用于 AI 评估展示。
- `FR-009` 入库前校验：全部片段完成双人评分后才允许正式入库。
- `FR-010` 入库粒度：以片段为单位写入，不以整视频覆盖或替换历史。
- `FR-011` 审计追踪：保留评分时间、评分人、模型版本、批次号。

## 7. Label Adjudication Rules

- 每个片段都必须存储三份原始评分：`AI`、`A`、`B`。
- 若 `A == B`，最终标签采用人工一致分（`human_consensus`）。
- 若 `A != B` 且 `AI == A` 或 `AI == B`，最终标签采用与 AI 一致的人工分（`ai_human_match`）。
- 若 `AI != A` 且 `AI != B` 且 `A != B`，标记为无效样本（`invalid`），不进入训练标签集。
- 无效样本仍需永久保留，供后续复核和规则分析。

## 8. AI Calibration Requirements

- AI 必须使用“有效最终标签”进行参数更新，不使用无效样本更新。
- 校准目标是提升 AI 与人工最终标签的一致率。
- 需记录校准批次、样本范围、模型版本、关键阈值变更与效果指标。
- 关键阈值示例：关键点位置/角度阈值（如膝、髋等规则参数）。

## 9. Data Model (Segment-Centric)

- `video`: 视频元数据、动作类型、分析区间、处理状态。
- `segment`: 片段 ID、视频 ID、重复序号、起止时间、机位标签。
- `score_ai`: 片段 ID、细分项 JSON、总分、模型版本、时间戳。
- `score_reviewer`: 片段 ID、reviewer_id、细分项 JSON、总分、时间戳。
- `label_result`: 片段 ID、最终标签、标签来源、有效状态。
- `dataset_entry`: 入库批次、片段 ID、三评分快照、创建时间。

## 10. Tech Stack and System Boundary

- 前端：`React + Vite`（当前 JavaScript，实现层可平滑迁移 TypeScript）。
- API：`NestJS/Fastify`（任务编排、权限、数据接口）。
- CV/算法：`Python + OpenCV + MediaPipe`（切分、识别、评分）。
- 存储：`PostgreSQL`（结构化数据）+ `S3/MinIO`（视频与片段文件）。
- 异步：`Redis + Queue`（视频分析任务异步执行）。

## 11. Non-Functional Requirements

- 文档先行：每次迭代先更新 `spec/backlog/adr` 再开发。
- 质量门禁：每次完成必须执行 `npm run check` 并记录结果。
- 可追溯性：任意样本可反查三评分、标签来源、模型版本。
- 可扩展性：无需重构核心数据模型即可扩展到 7 动作。
- 性能目标：60 秒视频在分钟级内完成 V1 基础处理。

## 12. Acceptance Criteria

- 可完整跑通 `上传 -> 切分 -> 片段播放 -> 三评分 -> 裁决 -> 入库` 闭环。
- 同一视频正/侧面混合时，片段级机位识别与评分流程可用。
- 任一片段可查询三份原始评分、最终标签、标签来源与有效状态。
- 三方评分全不一致样本不会进入训练标签集。
- 本次迭代交付必须通过 `npm run check`。
